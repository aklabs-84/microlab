# 🧪 "내가 만드는 규칙" 모드 — 계획서

> 목적: 학생이 "장치에게 어떻게 시킬까"를 **직접 설계하고, 해 보고, 고치는** 시간을 앱 안에 만든다.
> 원칙: **AI는 답을 주지 않는다.** (힌트·비교 도구로만 쓴다.) 연결과 실행은 자동이어도, 생각하는 일은 학생이 한다.
> 상태: 계획 (구현 전). 학생용 가이드는 앱을 다 만든 뒤에 만든다.

## 1. 지금 앱의 빈자리
- 대시보드: 값을 **본다**. 제스처: 동작을 **보여 준다**. 게임: **논다**.
- 학생이 센서값을 보고 "이럴 때 이렇게 반응시키자"를 **스스로 만드는 곳이 없다.**

## 2. 학생이 하는 일 (한 판의 흐름)
1. **미션 고르기** (또는 내 아이디어): 예) "책상을 두 번 두드리면 불이 켜지게 해 보자"
2. **관찰하기**: 센서 그래프를 보며 값이 언제 어떻게 변하는지 알아본다.
3. **규칙 만들기**: 블록 또는 글(코드)로 "센서가 이럴 때 → 이렇게 반응해라"를 짠다.
4. **실행하기**: 마이크로비트를 움직이면 화면의 가짜 LED와 진짜 LED가 반응한다.
5. **안 되면 고치기**: 왜 안 됐는지 그래프에서 찾고, 기준값·조건을 바꾼다.
6. **기록하기**: "내 생각 → 해 본 결과 → 고칠 점"을 한 줄씩 적는다. (코드 버전도 자동 저장)

## 3. 학년별 수준 (추천 배지만 붙이고 막지 않는다)
| 수준 | 대상 | 화면 |
|---|---|---|
| 🌱 블록 | 초 저~중학년 | 블록만. 쓸 수 있는 블록을 적게(센서 크기, 비교, LED 그림, 버튼) |
| 🌿 블록 + 코드 보기 | 초 고학년~중학교 | 블록을 끼우면 옆에 **같은 뜻의 글 코드가 보인다**(읽기 전용). 블록→글로 넘어가는 다리 |
| 🌳 글 코드 | 중 고학년~고등 | 글(JavaScript 일부)로 직접 쓴다. "블록으로 만든 걸 코드로 가져오기"도 가능 |

- 수준 칩 3개로 고른다. 교사가 주소에 `?level=block|bridge|text`를 붙이면 선택을 건너뛴다.
- 세 수준은 **같은 실행 엔진과 같은 기능**을 쓴다. 겉모양(블록/글)만 다르다.

## 4. 규칙의 모양 (블록과 글이 똑같이 표현할 수 있는 것)
- **센서값**: `x`, `y`, `z`(기울기), `세기`(흔들림 크기), 버튼 `A`/`B` 눌림
- **계속 반복**: 센서값이 올 때마다 실행 (초당 약 11~50번)
- **처음에 한 번**: 변수 준비
- **조건·비교·계산·변수**: 만약 / 아니면, `>` `<` `=`, 그리고 / 또는, 숫자, 변수 (세기, 횟수 세기 등)
- **반응**: `LED에 그림 보이기(하트/웃음/우는 얼굴/…)`, `LED 끄기`, `화면에 말하기`, `점프시키기`(4단계에서 게임 연결)
- 글 코드 예시:
  ```js
  let 횟수 = 0
  function 반복() {          // 센서값이 올 때마다 실행돼요
    if (세기 > 600) { 하트() ; 횟수 = 횟수 + 1 }
  }
  ```
  (이름은 한글/영어 둘 다 쓸 수 있게 별칭을 둔다. 확정은 구현 때 학생 입장에서 가장 쉬운 쪽으로)

## 5. 화면 구성 (`#/rules`)
- **위**: 수준 칩, 미션 선택, ▶ 실행 / ■ 멈춤
- **왼쪽**: 센서 그래프(기존 `LiveChart`). **기준선 보이기**: 규칙에서 쓰는 숫자(예: 600)를 가로선으로 그려서 "이 선을 넘으면 반응"이 눈에 보이게 한다.
- **오른쪽**: 편집 영역 (수준에 따라 블록 / 블록+코드 / 글)
- **아래**: 가짜 LED 5×5 화면 + 말하기 로그 + 오류 안내
- **시도 기록 패널**: 지금까지의 버전 목록(시간순), 한 줄 메모 3칸(생각/결과/고칠 점), 내보내기(복사)
- 연결이 없어도 **연습 모드(시뮬레이터)** 로 똑같이 해 볼 수 있다.

## 6. 안전한 실행
- 학생 코드는 **Web Worker**에서 실행한다. 무한 반복을 만들어도 화면이 멈추지 않고, 한 번 실행이 길어지면 자동으로 멈추고 "무한 반복인 것 같아요. 반복 안에서 끝나지 않는 일이 있는지 봐요"라고 알려 준다.
- 오류 메시지는 어려운 영어 대신 **쉬운 한국어 + 어느 줄**로 보여 준다. (정답을 알려 주지 않고 어디를 볼지만 알려 준다)
- 규칙은 `icon:` 명령으로만 장치를 움직인다. **펌웨어 변경 없음**, 기존 프로토콜 그대로.
- 학생 코드·기록은 이 브라우저(localStorage)에만 저장한다. API 키 같은 비밀 값은 쓰지 않는다.

## 7. 미션 카드 (정답을 보여 주지 않는 열린 미션)
- 예: ① 흔들면 하트 ② 책상을 두 번 두드리면 켜지기 ③ 기울이는 방향으로 화살표 보이기 ④ 가만히 있으면 졸린 얼굴 ⑤ "내가 정하는" 자유 미션
- 각 미션에 **"생각해 볼 질문" 2~3개**만 둔다. (예: "흔들 때 값은 어떻게 변할까?", "기준값을 너무 낮추면?") 해결 코드는 넣지 않는다.
- 미션 목록은 데이터 파일 한 곳에 두어 교사가 쉽게 추가·수정한다.

## 8. 파일 계획 (한 번에 하나씩)
| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `shared/rules/worker.js` + `shared/rules/engine.js` | 글 코드를 Worker에서 실행, 센서값 넣고 반응(LED·말하기·점프)을 받아 온다. 시간 제한, 쉬운 오류 |
| 2 | `shared/ui/chart.js` (작은 수정) | 가로 기준선 그리기 옵션(`lines`) 추가 |
| 3 | `modes/rules/rules.js` | 화면 전체(글 코드 수준 먼저), 가짜 LED, 로그, 연습 모드 동작 |
| 4 | `modes/rules/notes.js` | 버전 자동 저장 + 한 줄 메모 + 내보내기 |
| 5 | `modes/rules/missions.js` | 미션 데이터 |
| 6 | `vendor/blockly/…` + `modes/rules/blocks.js` | 블록 편집기(한국어), 블록→글 변환(🌿의 코드 보기, 🌳의 가져오기) |
| 7 | `js/modes.js` | 🧪 카드 한 줄 |
| 8 | `modes/game/game.js`, `modes/game3d/game3d.js` | **조종 방식 선택: AI 동작 / 내 규칙** (4단계) |

## 9. 단계(마일스톤)
- **1단계 (핵심)**: 글 코드 수준 + 그래프 기준선 + 가짜 LED + 연습 모드 → 파일 1~3, 7
- **2단계**: 시도 기록 + 미션 → 파일 4, 5
- **3단계**: 블록 편집기와 세 수준 완성 → 파일 6
- **4단계**: 게임 연결, "내 규칙 vs AI" 점수 비교 → 파일 8
- **이후**: AI 힌트 모드(말로 시키는 코딩을 "코드 대신 질문·힌트"를 주는 방식으로 바꿔서), 클래스로그AI 제출 연동, 학생용 가이드(`student-guide`)

> 글 코드부터 먼저 만드는 이유: 엔진·그래프·기록이 블록과 글에 똑같이 쓰이므로, 겉모양(블록)은 마지막에 얹는 게 안전하다.

## 10. 확인 방법 (단계마다)
- 연습 모드에서 규칙을 실행해 그래프·가짜 LED가 반응하는지 확인하고 화면을 캡처한다.
- 일부러 무한 반복·오류 코드를 넣어 화면이 멈추지 않고 쉬운 안내가 뜨는지 확인한다.
- 마지막에 실제 v2 보드(USB/블루투스)로 진짜 LED가 반응하는지 확인한다.

## 11. 위험과 결정할 점
| 항목 | 내용 | 대응 |
|---|---|---|
| Blockly 크기 | 라이브러리가 수백 KB~1MB | 3단계에서 `vendor/`에 저장(인터넷 없이도 가능). 필요한 부분만 쓰는 방식도 검토 |
| 블록 → 글 변환의 한글 | 블록이 만든 코드의 이름 | 블록 전용 변환기를 직접 정의해서 한글 이름 사용 |
| 글 코드 입력의 어려움 | 키보드 타이핑 부담 | 예시 코드 조각 버튼, 오류 시 줄 표시, 자동 닫기 괄호 |
| 블루투스 속도 | 센서값 11개/초 → 빠른 동작은 놓칠 수 있음 | "왜 안 잡힐까?"도 학생이 고민할 거리로 두되, 안내 문구로 설명 |
| 이름 쓰기 | 앱 이름은 'AKLABS', 클래스로그AI 표기 규칙 유지 | 제출 연동 때 적용 |
